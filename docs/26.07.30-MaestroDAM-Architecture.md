# 26.07.30 — MaestroDAM Architecture

**Status:** Draft v1 (2026-07-30)
**Goal:** A Digital Asset Management (DAM) app inside SwiftMaestro that competes with Adobe Bridge and NeoFinder — local-first, AI-native, and integrated with the existing agent workspace.

---

## 1. Why / Positioning

| Competitor | Weakness we exploit |
|---|---|
| **Adobe Bridge** | Subscription-locked, no local AI keywording, slow on huge libraries, cloud-tethered |
| **NeoFinder** | Dated UI, no AI, weak video/RAW previews, no agent integration |
| **digiKam** | Powerful but KDE/Qt UI is alien on macOS; no native MLX AI |
| **PhotoPrism/immich** | Server + Docker; not a native Mac app; no agent workflows |

**MaestroDAM's edge:** fully local catalog (GRDB/SQLite) + native macOS UI (SwiftUI tiling workspace) + on-device AI keywording/captioning via the existing VisionProxy (Qwen3-VL + Apple Vision OCR) + agent access — the user can ask an agent "find all RAW files from the Broken Hill shoot rated 4+ with kangaroos" and the agent queries the DAM catalog via `execute_sqlite`.

Existing head start inside SwiftMaestro:
- Vision keywording pipeline already ran against **346,829 photos** (2026-07-07 run)
- `SpotlightMetadataExtractor` (NSMetadataQuery — EXIF, Finder tags, color labels)
- `execute_sqlite` (GRDB) already exposed to agents
- `index_directory` / `save_index` tooling
- xattr keyword system proven on the MyStory project
- `Tethering/` module (PTP/NDI capture) — future direct-to-catalog ingest

## 3. Architecture

### 3.1 Module layout (new: `Sources/DAM/`)

```
Sources/DAM/
├── DAMModels.swift          — GRDB records: Asset, Collection, CollectionAsset,
│                              Tag, AssetTag, MetadataCache, ThumbnailCache
├── DAMDatabase.swift        — DatabaseQueue + DatabaseMigrator (v1 schema)
├── DAMImportService.swift   — folder/volume scan → catalog upsert; xattr keyword
│                              harvest; Spotlight metadata enrichment
├── ThumbnailService.swift   — QLThumbnailGeneration pipeline + disk cache
├── DAMViewModel.swift       — @Observable @MainActor browser state
└── DAMBrowserView.swift     — SwiftUI grid/loupe browser (workspace panel)
```

Panel wiring: `WorkspacePanelKind.damBrowser` → `AppCategory.swiftApps` → `WorkspacePanelContentView` case. Follows the exact pattern used by `webBrowser` (2026-07-30).

### 3.2 Catalog database

Location: `~/Library/Application Support/SwiftMaestro/dam/catalog.sqlite` (GRDB `DatabaseQueue`, WAL mode).

**Schema v1** (SQLite):

```sql
CREATE TABLE asset (
    id INTEGER PRIMARY KEY,
    path TEXT NOT NULL UNIQUE,          -- absolute path (bookmarked volumes use relative + volumeUUID later)
    filename TEXT NOT NULL,
    uti TEXT,                           -- uniform type identifier
    fileSize INTEGER,
    fileModDate REAL,                   -- unix epoch
    width INTEGER, height INTEGER,
    duration REAL,                      -- video/audio
    rating INTEGER DEFAULT 0,           -- 0–5, Bridge-compatible
    colorLabel TEXT,                    -- none/red/orange/yellow/green/blue/purple (Finder + Bridge parity)
    flag TEXT,                          -- none/pick/reject
    captureDate REAL,                   -- EXIF DateTimeOriginal when present
    cameraMake TEXT, cameraModel TEXT,
    lensModel TEXT,
    iso INTEGER, aperture REAL, shutterSpeed TEXT, focalLength REAL,
    gpsLat REAL, gpsLon REAL,
    orientation INTEGER DEFAULT 1,
    perceptualHash TEXT,                -- dHash for dedupe (phase 3)
    xattrKeywords TEXT,                 -- raw com.apple.metadata:_kMDItemUserTags snapshot
    aiCaption TEXT, aiKeywords TEXT,    -- VisionProxy output
    ocrText TEXT,                       -- Apple Vision OCR (signs, documents)
    indexedAt REAL, aiIndexedAt REAL
);
CREATE INDEX idx_asset_rating ON asset(rating);
CREATE INDEX idx_asset_captureDate ON asset(captureDate);
CREATE INDEX idx_asset_path_prefix ON asset(path);

CREATE TABLE tag (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    parentId INTEGER REFERENCES tag(id),   -- hierarchical tags (digiKam model)
    source TEXT DEFAULT 'user',            -- user | xattr | ai | ocr | exif
    UNIQUE(name, parentId)
);
CREATE TABLE assetTag (
    assetId INTEGER REFERENCES asset(id) ON DELETE CASCADE,
    tagId INTEGER REFERENCES tag(id) ON DELETE CASCADE,
    PRIMARY KEY (assetId, tagId)
);

CREATE TABLE collection (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    kind TEXT NOT NULL,                 -- folder | smart | manual
    predicateJSON TEXT,                 -- smart-collection rule set
    parentId INTEGER REFERENCES collection(id)
);
CREATE TABLE collectionAsset (
    collectionId INTEGER REFERENCES collection(id) ON DELETE CASCADE,
    assetId INTEGER REFERENCES asset(id) ON DELETE CASCADE,
    position INTEGER,
    PRIMARY KEY (collectionId, assetId)
);

-- FTS5 over everything textual
CREATE VIRTUAL TABLE assetSearch USING fts5(
    filename, aiCaption, aiKeywords, ocrText, xattrKeywords,
    content='asset', content_rowid='id'
);
```

Schema notes:
- Ratings/labels/flags mirror Bridge/darktable so XMP round-tripping is lossless (see darktable `src/common/ratings` + digiKam `PickLabel/ColorLabel`).
- Hierarchical tags follow digiKam's `TagsTree` (parent chain `/People/Family/Celeste`).
- FTS5 gives instant filename/caption/OCR search; Spotlight (`NSMetadataQuery`) stays as a cross-check, not the primary index (Spotlight silently skips unindexed volumes — unacceptable for external drives, which is NeoFinder's whole market).

### 3.3 Metadata strategy (read vs write)

| Operation | Tool |
|---|---|
| Read EXIF/IPTC/XMP (import) | `ImageIO` (`CGImageSourceCopyProperties`) — fast, native, no subprocess |
| Read Finder tags / xattr keywords | `xattr` directly (`com.apple.metadata:_kMDItemUserTags` bplist) — swift-xattr pattern |
| Read PDF/office/audio/video metadata | `SpotlightMetadataExtractor` (NSMetadataItem) as fallback |
| **Write** ratings/keywords back to files | **exiftool subprocess** (`-xmp:rating=`, `-xmp:subject=`, sidecar vs embedded per file type) — bundled binary, two-stage scanned |
| XMP sidecars for RAW | darktable-style `.xmp` alongside the RAW; never write into proprietary RAW containers |

### 3.4 Thumbnails & previews

- `QLThumbnailGeneration` (QuickLookThumbnailing) for 400+ file types incl. RAW — this is what NeoFinder can't do well.
- Disk cache: `~/Library/Caches/SwiftMaestro/dam-thumbs/<assetID>-<size>.jpg`, LRU-trimmed, keyed by `(assetID, mtime)` so edits invalidate automatically.
- Grid uses small (256px) thumbs; loupe/filmstrip uses 1024px; full-res zoom loads the original lazily.
- Prefetch: `LazyVGrid` + actor-isolated cache with request coalescing (digiKam's thumbnail thread model, minus Qt).

### 3.5 AI layer (the differentiator)

All on-device, reusing existing services:

1. **Keywording/captioning** — VisionProxyService (Qwen3-VL-8B, 1280px) writes `aiCaption` + `aiKeywords` → tags with `source='ai'`. Batch mode = the proven 346K-photo pipeline, now writing into the catalog instead of standalone files.
2. **OCR** — Apple Vision `VNRecognizeTextRequest` at full res → `ocrText` (already integrated in VisionProxy).
3. **Faces** — `VNDetectFaceRectanglesRequest` → face regions; later `VNPerson` clustering (photoPrism-style) in phase 3.
4. **Semantic search** (phase 3) — CLIP embeddings via `mlx-embeddings` (already cloned) → vector column + ANN query; immich's job-queue model for throughput.
5. **Dedupe** — dHash perceptual hash + Hamming distance clustering (phase 3).

### 3.6 Agent integration

- New tools: `dam_search` (natural language → SQL over catalog), `dam_tag_batch`, `dam_import_folder`. Registered in `MaestroTools` following the `index_directory` pattern (`fileOpToolNames`).
- Agents can already `execute_sqlite` the catalog directly — documented views make this safe.
- System prompt gets a DAM section (like the DIRECTORY INDEXING block).

### 3.7 Volumes & offline media (NeoFinder killer feature)

- Catalog persists assets from **offline volumes**: store `volumeUUID` + relative path; UI shows greyed thumbnails for offline assets (cached thumbs still viewable) — this is NeoFinder's entire value proposition, done natively.
- Volume scan: watch mount/unmount via `NSWorkspace` notifications; rescan delta via mtime+size fast path.

### 3.8 Ingest (from camera/SD)

- Reuse `DJICameraOffloader` patterns + `Tethering/` module: import dialog → copy with verify (xxHash) → rename template → backup second destination → auto-catalog on arrival.

## 4. Phased roadmap

- **Phase 0 (this scaffold, 2026-07-30):** module skeleton — GRDB schema v1, folder import (ImageIO + xattr), QuickLook thumbnails, grid browser panel in workspace. Build green.
- **Phase 1:** ratings/labels/flags + keyboard culling (StreamDeck plugin knowledge), tag tree UI, search bar over FTS5, filmstrip + loupe.
- **Phase 2:** exiftool write-back + XMP sidecars, smart collections, volume/offline handling, agent tools (`dam_search` etc.).
- **Phase 3:** AI batch keywording into catalog, faces, dedupe, CLIP semantic search, ingest-from-SD workflow, compare/survey mode, export/share extensions.

## 5. Performance targets

- 500K assets cataloged; grid scroll at 60fps on M1 Max (thumbnail cache + prefetch).
- Folder scan ≥ 5,000 files/min (ImageIO fast path, no full decode).
- FTS query < 50ms over 500K rows; Spotlight never on the critical path.

## 6. Security & privacy (project policy)

- 100% local — no telemetry, no cloud. Catalog lives in Application Support; backups via Chezmoi where appropriate.
- Bundled exiftool binary gets the mandatory two-stage scan before first use.
- No PII in repo; `woodsee` name allowed per policy.
