# 26.08.04-SocialPlugins-Plan

**Status:** Complete (code) — pending user runtime testing
**Date:** 2026-08-04

## Goal

Add Bluesky and Patreon as SwiftMaestro plugins (WKWebView panel plugins, Mastodon pattern), plus matching native agent tools that reuse the plugins' Keychain sessions — authenticate once in the panel, agents can act too.

## What shipped

### 1. Bluesky plugin — `Sources/Resources/Plugins/bluesky/`
- `manifest.json` — capabilities `["network", "secrets"]`, icon `at`
- **Anonymous mode**: search posts/people, profiles, author feeds, threads via `https://api.bsky.app` (no auth)
- **Sign-in**: handle + app password (+ optional custom PDS) → `com.atproto.server.createSession`; tokens in Keychain (`plugin.bluesky.*`), never localStorage
- **Authenticated**: home timeline, post (300-grapheme count, link facets), like/unlike, repost/unrepost, auto session refresh on `ExpiredToken`
- Facet-aware text rendering (UTF-8 byte offsets), embeds: images, external cards, quotes, recordWithMedia

### 2. OAuth bridge capability (native)
- `PluginCapability.oauth` — unlocks `swiftMaestro.startOAuth({ authorizeURL, state, port?, timeoutSeconds? })`
- `Sources/Services/OAuthLoopbackServer.swift` — generalized from `XeroLoopbackServer` (left untouched); **loopback-only** binding (`requiredInterfaceType = .loopback`), state validation, timeout, provider-denied handling; returns full query dict
- `PluginBridge.performOAuth` — https-only authorize URLs, port 1024–65535, timeout 15–600 s; token exchange stays in JS via `fetch` (host never sees client secrets/tokens)

### 3. Patreon plugin — `Sources/Resources/Plugins/patreon/`
- `manifest.json` — capabilities `["network", "secrets", "oauth"]`, icon `heart.circle`
- **Creator mode**: Creator's Access Token (+ optional client id/secret/refresh for auto-refresh) → dashboard (patron count, tiers), members list (tier, status, amounts — null-safe for Patreon's 2026 identity masking), posts feed; cursor pagination
- **Patron mode**: full OAuth via `startOAuth` (user's own v2 client, redirect `http://127.0.0.1:53124/callback`) → identity + memberships view. Patreon exposes no cross-creator post feed to ordinary OAuth clients — patron mode is memberships-only by design
- Mandatory `User-Agent`, explicit `fields[]`/`include` JSON:API params, 429 `retry_after_seconds` backoff, 401 → refresh → retry

### 4. Native agent tools (Keychain-shared sessions)
- `MaestroTools+Bluesky.swift` (extended): `get_bluesky_timeline`, `post_bluesky`, `like_bluesky_post`, `unlike_bluesky_post`, `repost_bluesky_post`, `unrepost_bluesky_post` — session loaded from `plugin.bluesky.*`, one refresh+retry on expiry, link facets with UTF-8 byte offsets, 300-grapheme validation
- `MaestroTools+Patreon.swift` (new): `get_patreon_campaign`, `list_patreon_members`, `list_patreon_posts`, `get_patreon_memberships` — auth from `plugin.patreon.*`, refresh flow, mandatory User-Agent, mode-aware errors ("needs creator/patron mode")
- `ToolCategory.patreon` added; bluesky/patreon visible + default-enabled for both agent kinds

### 5. project.yml fix (pre-existing latent bug)
- `exclude:` (singular) was silently ignored by xcodegen → corrected to `excludes:`
- `Resources/Plugins/**` excluded from the `Sources` glob — plugins ship only via the folder reference (was: duplicate flattened copies; with two plugins same-named files collided → build failure)
- Removed dead top-level `resources:` block (also silently ignored; those files load from bundle root via the glob)

## Runtime testing (user, per repo rule — agents never launch the app)
1. Bluesky panel: browse anonymously → search posts/people → sign in with app password → timeline, post, like/repost
2. Agent: "post to Bluesky: …" after signing in via panel
3. Patreon panel: creator token → dashboard/members/posts; patron OAuth login → memberships
4. Agent: "how many patrons do I have?" after creator connect

## Known constraints
- Bluesky plugin composer creates link facets only (mentions/tags resolve as plain text)
- Patreon API: no post-creation endpoint; patron mode can't read other creators' posts (Patreon scope policy)
- Shopify ToS note from the earlier Maestro Shop plan remains a pre-ship review item for that (separate) feature
